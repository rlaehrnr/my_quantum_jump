# StockInfo 자동 갱신 설계

**작성: 2026-08-12** · 상태: 확정 (사용자 승인)

## 배경

소형주 화면은 종목별 **액면가**와 **상장주식수**를 쓴다.

- 액면가 — 표에 열로 뜨고, 현재가가 액면가보다 낮으면 그 줄을 강조한다(`pages/5_...py:303`). 액면가 미달은 관리종목 지정 사유라 미리 경고하는 용도다
- 상장주식수 — 시가총액 백업 계산용. 자동으로 시총을 못 가져온 종목만 `상장주식수 × 현재가`로 채운다(`:273`)

이 두 값은 자동 수집원이 없어서 사용자가 KRX에서 받아 구글 시트 `StockInfo` 탭에
**생각날 때마다 손으로** 붙여넣어 왔다. 시트의 기준일 메모는 `2026-05-08`이다.

## 목적

손으로 하던 갱신을 GitHub Actions 로봇으로 옮긴다. 사용자가 매월 할 일은 없어진다.

## 결정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 데이터 소스 | pykrx `get_market_ohlcv_by_market("ALL")` | 필요한 5개 컬럼을 한 번에 준다. FinanceDataReader는 상장주식수만 주고 **액면가가 없다**(2026-08-12 실측) |
| 저장 위치 | `data/krx_stock_info.csv` | 아래 §저장 위치 참고 |
| 갱신 주기 | 매월 15일 09:00 KST | 액면가는 액면분할 때만 바뀐다. 상장주식수도 시총 백업으로만 쓰여 월 단위로 충분하다. Actions 사용량 월 +1분 |
| 수집 범위 | `ALL` (KOSPI·KOSDAQ·KONEX) | 필터링 코드를 없앤다. 호출 횟수·파일 크기가 사실상 같고, KONEX 종목을 담게 돼도 커버된다 |

### 저장 위치 — 구글 시트가 아니라 레포 CSV인 이유

처음엔 시트 직접 갱신을 택했다가, 보안을 따져보고 CSV로 바꿨다.

시트에 쓰려면 구글 서비스 계정 키를 GitHub Secrets에 **복사**해야 한다. 구글 시트 권한은
파일 단위라 "StockInfo 탭만 쓰기"가 불가능하다. 즉 그 키는 `ddo`·`sso`·`mom`도 읽을 수 있다.
**보유 종목을 읽을 수 있는 키를 GitHub에 한 벌 더 두는 셈**이다.

GitHub 공식 문서도 이 형태를 경고한다 — *"do not use a blob of JSON, XML, or YAML (or similar)
to encapsulate a secret value, as this significantly reduces the probability the secrets will be
properly redacted."* 서비스 계정 키가 정확히 JSON 덩어리다.

CSV로 가면 GitHub에 들어가는 비밀은 `KRX_ID`/`KRX_PW`뿐이고, 둘 다 유출돼도 조회용 계정이라
잃을 게 없다. **구글 키는 Streamlit 한 곳에만 남는다.** 대가는 앱 코드 수정이다(§앱 변경).

부수 효과 — 앱이 구글 시트를 4번이 아니라 3번 호출하게 되고, 하필 제일 무거운
2,871행 호출이 빠진다. 액면분할·증자 이력도 git diff로 남는다.

## 데이터 흐름

```
매월 15일 09:00 KST
│
├─ GitHub Actions ─ update_stock_info.py
│    1) pykrx 로그인            KRX_ID·KRX_PW ← GitHub Secrets
│    2) 전종목 기본정보 수집      get_market_ohlcv_by_market("ALL")
│    3) 5개 컬럼 추출·정규화
│    4) data/krx_stock_info.csv 덮어쓰기
│    5) 변경분 있으면 커밋 & push
│
└─ Streamlit 앱 (push에 의해 자동 재배포)
     pages/5 가 시트 대신 이 CSV를 읽는다
```

기존 로봇 9개와 같은 패턴이다. 새로 생기는 건 스크립트 1개 + 워크플로우 1개.

## CSV 스키마

```
종목코드,종목명,시장구분,액면가,상장주식수
098120,마이크로컨텍솔,KOSDAQ,500,8312766
009520,포스코엠텍,KOSDAQ GLOBAL,500,41642703
```

| 컬럼 | pykrx 원본 | 비고 |
|---|---|---|
| 종목코드 | 티커(인덱스) | **6자리 문자열**. 앞자리 0을 보존한다 |
| 종목명 | 한글종목약명 | 시트에 쓰던 것과 같은 필드 |
| 시장구분 | 시장구분 | `KOSPI` / `KOSDAQ` / `KOSDAQ GLOBAL` / `KONEX` |
| 액면가 | 액면가 | 숫자가 아닌 값(무액면 등)이 올 수 있다. 읽는 쪽이 0으로 처리한다 |
| 상장주식수 | 상장주식수 | 정수 |

읽을 때 `dtype=str`을 명시해 종목코드가 숫자로 해석되지 않게 한다. 오늘 고친
종목코드 버그(`현황.md` §5)와 같은 계열이라 처음부터 막는다.

## 앱 변경

`pages/5_내 소형주 퀀트 포트.py`의 `load_stock_info_from_gsheet()`를 CSV를 읽는
함수로 교체한다. **반환값 모양은 그대로 유지**한다.

```
{종목코드: {'액면가': int, '상장주식수': int}}
```

이 함수를 쓰는 `:268`, `:273`은 고치지 않는다. 이미 정의만 돼 있고 쓰이지 않던
`FACE_VALUE_PATH = 'data/krx_stock_info.csv'`(`:16`)가 제 역할을 하게 된다.

## 실패 처리

**로그인 실패나 수집 결과가 0행이면 CSV를 건드리지 않고 에러로 끝낸다.**

빈 파일로 덮으면 액면가 경고가 조용히 사라진다 — `현황.md`에 기록된 `except: pass`
함정과 같은 실패 양상이다. 기존 파일을 보존하고 Actions를 실패로 표시해 눈에 띄게 한다.

앱 쪽은 CSV가 없으면 빈 dict를 반환한다. 지금 시트를 못 읽을 때와 같은 동작이라
화면이 깨지지 않는다.

## 보안

- GitHub Secrets는 포크 PR로 트리거된 워크플로우에 전달되지 않는다. 이 레포 워크플로우는 `schedule` + `workflow_dispatch`만 쓴다
- pykrx가 로그인 시 ID를 stdout에 출력한다(`pykrx/website/comm/auth.py:189`). Secrets로 넣으면 GitHub이 `***`로 가린다. **워크플로우에 `echo`나 디버그 출력을 추가하지 않는다**
- KRX 비밀번호는 다른 곳에서 쓰지 않는 전용 비밀번호를 쓴다

## 검증 계획

로컬에는 KRX 자격증명이 없다(Secrets 안에 있고 읽을 수 없다). 그래서 두 단계로 나눈다.

1. **로컬** — CSV를 읽는 앱 함수를 실제 소스에서 꺼내 단위 테스트한다. 정상 CSV, 파일 없음, 액면가 비숫자, 앞자리 0 종목코드를 케이스로 둔다
2. **Actions** — `workflow_dispatch`로 **수동 1회 실행**한다. 행 수와 알려진 값(예: `005930` 삼성전자 액면가 100)을 대조한다
3. 결과를 확인한 뒤에 자동 스케줄을 켠다

## 건드리지 않는 것

- **구글 시트 `StockInfo` 탭** — 지우지 않고 그대로 둔다. 앱이 안 읽을 뿐이다. 되돌리고 싶어지면 그대로 있다
- `Config`·`ddo`·`sso`·`mom` 탭과 그것을 읽고 쓰는 코드
- 기존 로봇 9개
